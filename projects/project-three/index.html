The Motivation

A resume only fits one page. I wanted one place that shows everything on mine, plus the parts it can't: who I am, what motivates me, what I love, and who I want to become.

So instead of a template, I built my own. Every page, from my internships to my golf career, is something I designed and wrote myself.

How It Works

The site is plain HTML, CSS, and JavaScript with no framework. One shared stylesheet acts as a small design system, so every page uses the same colors, type scale, and spacing.

The code lives in a public GitHub repo. Every push to main deploys automatically to GitHub Pages, and I preview changes on a local server before anything goes live.

How I Built It

This site wasn't written entirely by hand, and it wasn't handed off to AI either. My computer science background in HTML and CSS means I understand every part being built. Claude helps me spin up new pages faster and keep the whole site cohesive, and I go into the code myself to edit, write, and fine-tune the details.

I started with a written project brief: goals, a sitemap, a design reference, and a tech stack. From there, every feature followed the same loop.

  1. 01

    Describe it

    Write a specific prompt: the layout, the behavior, and what it has to stay consistent with.

  2. 02

    Build it

    Claude Code drafts the HTML and CSS in my project folder, then I read through it and make my own edits.

  3. 03

    Review it

    I check it on my local server, screenshot what looks off, and refine it until it's right.

  4. 04

    Ship it

    Commit with a clear message, push to GitHub, and the live site updates.

Seeing Edits in Real Time

Early on, every change meant committing, pushing to GitHub, and waiting for GitHub Pages to rebuild before I could see it. That's slow when you're nudging a photo a few pixels at a time.

Now I run a local server from my project folder with one command. The site loads at localhost, I refresh to see each edit instantly, and I only push to GitHub once a page is ready to go live.

How I Learned

My computing degree from Saint Mary's and my master's work at Notre Dame gave me the foundation. Shipping a real website taught me the rest.

I learned Git by committing every change, learned to deploy by putting my own site on the internet, and learned to debug by figuring out why a header wouldn't line up. Most of all, I learned how to talk to an AI tool like a teammate: clear goals, specific feedback, and never accepting the first draft.

What I Learned

AI makes building faster, but it doesn't make the decisions. Every layout, word, and photo on this site went through rounds of my own feedback, often down to a few pixels.

The biggest lesson was that good prompts are just good communication. The more precisely I could describe what I wanted, and why, the better the result.

What's Next
